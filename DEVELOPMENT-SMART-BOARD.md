# Subject board and bilingual smart entry — 3.2.0

Tasks now default to a subject board with the account's real parts/projects in a compact rail and real subjects/sections as columns, including empty subjects. List and list-with-details remain selectable; phones use a visible layout selector and horizontally scrolling columns. Card checkboxes act directly, full editing remains one click away, and subject moves use the existing version-checked `task.edit` path. Desktop drag and drop has an accessible move-to-subject menu alternative. Existing Todoist project/section/task identities are reused.

All new-task entry points use one draft-preserving smart composer. Typing `eng` offers English Language and English Literature (plus any other real matching subjects), with ↑/↓ selection and Tab confirmation; ambiguous subjects are never silently assigned. Aliases cover the user's existing English and Chinese school/life areas while custom subject names work through prefix matching. Chinese IME composition is excluded from completion/save keyboard shortcuts. Touch users can tap the same candidates. Subject choices always carry their part ID.

The local parser recognises common English/Chinese durations, relative/explicit dates, clock times and ranges, AM/PM and Chinese day periods. Examples: `1hr`, `20min`, `1h30m`, `一小时半`, `明天下午三点到四点`, `tomorrow 15:00–16:00`. It shows extracted metadata and a clean task preview before Save. Recognition can be disabled per token to retain literal title text. Quoted text, URLs, file paths, emoji and chapter/page ranges are protected. Invalid dates/times require correction; no external AI or per-keystroke provider calls are involved.

An explicit start/end, or start plus typed duration, creates one managed private calendar block atomically with the task. `plannedEnd` is an optional ISO instant, distinct from a confirmed deadline, estimated effort and actual sessions. An explicit 60-minute calendar window plus a 20-minute estimate retains both values. Dates/time changes carry a window's duration; full editing can change/clear its end independently. Moving the managed calendar block updates its task's date/time/title; deleting it preserves the task. Source refreshes retain window duration while following the Todoist scheduled start. End instants/estimates remain planner data; this release does not add Todoist duration or iCloud export semantics to these managed windows.

Managed windows use `task-window:<task-id>` with `taskWindow: true`. Their reminder identities reuse the existing scheduled-task identities, preventing duplicate notifications when only an end is added/removed. They have no completion, XP or fixture-pass effect. Recurring skip/undo also carries the explicit window. Independent ordinary calendar blocks remain separate.

Task display preferences gain a version-2 layout default. Legacy version-1 preferences transition once to the new board while retaining sorting and custom fields; later layout choices persist. Existing schema-7 task records gain only optional `plannedEnd` and block-marker fields. No SQL migration, reseed, asset change or football-engine change. Encrypted recovery includes the new preferences and windows; draft input is local to the device and excludes task status/provider identity fields.
