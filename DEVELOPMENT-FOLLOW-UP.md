# Recurring skips and next-day review — 3.1.0

Recurring tasks offer **Skip this occurrence** from the task actions menu, full editor, Hub expansion, reminder controls and unfinished-task review. Skipping moves the suggested schedule with a normal Todoist due-date update. It never closes/completes a task, grants XP/work credit, alters a confirmed deadline, changes the recurrence rule, or removes actual sessions. Each skip has a stable ID and preserved history; retry is idempotent. Undo is accepted only while the task still has the skipped schedule and reward scope, so a later device/provider edit is never overwritten.

The date chooser suggests the next date for unambiguous daily, weekly, weekday, named-weekday, interval, monthly and yearly rules. Complex rules deliberately ask the user to choose the next scheduled date; no guessed parser result is silently applied. Month-end and leap-year suggestions skip invalid dates rather than clamping them.

One grouped reminder at **09:00 Asia/Shanghai by default** covers unresolved earlier suggested days, past confirmed deadlines and past one-off blocks for otherwise undated tasks. Dates are preserved. Actions are Complete, Reschedule, Keep for now and (for recurring tasks) Skip this occurrence. Keep suppresses that task from the current day's group, with unfinished work returning the following day. Undated backlog, unreviewed imports, completed/deleted/archived tasks, muted areas and tasks with reminders disabled do not generate the group.

Morning review time is configurable under Settings → Reminders. The scheduler moves reviews out of quiet hours, catches up once after an outage, suppresses unfinished-work pushes when source verification fails, and reuses stable per-day notification identities. Restoring a backup cannot replay an earlier morning notification. The Hub, task-filter bar and coach inbox expose the same current review even when device push permission is unavailable.

Persistence is backward-compatible: optional task skip/review fields and a defaulted `carryoverTime` preference use the existing schema-7 state document. No SQL migration, production reseed or career-engine change. Encrypted archives retain the added fields.
