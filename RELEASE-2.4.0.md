# Questbound FC 2.4.0 — career-menu design and motion

A focused presentation update in the user's old FIFA direction. Original pitch-line graphics, stronger typography, cyan/purple selection highlights, poster-like career tiles and consistent panel materials extend across the existing three themes. No purchased or additional third-party assets or dependencies.

- Task rows retain the compact title/date/priority overview and direct full-editor action. Priority flags receive a clearer tinted badge and coloured edge. Details expand and collapse to their real content height; collapsed controls become inert and leave the accessibility tree immediately. Long notes and all existing task actions remain available.
- Short page and view entrances, bounded row/tile staggering, deliberate button press feedback, menu reveals and progress transitions. Hover effects apply to precise pointers. No perpetual decorative animation was added.
- Dialogs enter and dismiss smoothly. Closing retains the existing focus trap and background protection, then returns focus to the original trigger even when an editor input uses autofocus. Escape dismisses the nearest date layer before the dialog. Draft persistence and conflict review are unchanged.
- Phone spacing is tighter so the first task reaches the initial screen, while core buttons and timer controls retain 44 px touch targets. English/Chinese and all three existing theme IDs remain compatible. Device and account reduced-motion preferences disable the new motion.

Browser verification used the isolated local preview account, with no connected providers. Checked Night Stadium, Classic Career and Training Day in English/Chinese; desktop width 1200, phone width 390 and a narrower 325 px layout without horizontal overflow. Verified task open/close and Enter/E keyboard entry, full editing, Escape focus return, draft recovery through theme/language changes, and reduced-motion transitions at 0 s. A running focus timer retained its identity through theme/language/reduced-motion switches and reload, then paused, resumed and saved correctly. The short local test session earned no XP. The existing 3D player loaded in the hub; its model, materials, saved appearance and controls were not changed.

These checks must complete before handoff. Schema remains 5; no provider, database, reward, reminder or backup logic is changed.
